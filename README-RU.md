## ✨ Преимущества этой ветки (сравнение с апстримом)

Этот репозиторий — расширенная ветка [xenmods/DLSSNR-Cost-Scaler](https://github.com/xenmods/DLSSNR-Cost-Scaler) (апстрим v1.0.5 полностью синхронизирован). Апстрим — чисто алгоритмический прокси с настройкой через правку ini и перезапуск игры; эта ветка превращает его в **инструментарий настройки в реальном времени «что видишь, то и получаешь»** и глубоко перерабатывает чередование кадров при шумоподавлении:

| Возможность | Апстрим | Эта ветка |
| --- | :-: | :-: |
| Настройка | Правка ini вручную + перезапуск | **Внутриигровая панель / консоль / менеджер — изменения применяются мгновенно** |
| Многосторонняя синхронизация | Нет | Панель ⇄ консоль ⇄ разделяемая память ⇄ прокси, синхронизация за миллисекунды |
| Графическая установка / удаление | Переименование и копирование вручную | **Менеджер рекурсивно сканирует библиотеку игр; установка / удаление / восстановление в один клик** |
| Пропуск кадров VRNR | Фиксированные чередующиеся кадры | **Визуальный переключатель + полная цепочка анти-мерцания** (база 0.6.3 → 0.7.1 нижний порог веса / репроекция MV / защита силуэтов → 0.7.3 адаптация к FPS) |
| FPS Governor | Нет | **Автоматическое пошаговое масштабирование для удержания целевого FPS**, с поддержкой множителя Frame-Gen (0.7.0, синхронизация с апстримом) |
| Интерфейс | — | Стиль M3E, светлая и тёмная темы, 中 / EN / RU / 한 |
| Безопасность | — | SEH-защита от сбоев; исключения шейдеров не «роняют» игру |

## 🆕 Новые возможности

### Настройка с синхронизацией трёх клиентов

- **Внутриигровая панель** (`Ctrl+Alt+F11`): поверх всех окон, перетаскивается, свободно масштабируется; не перехватывает фокус и не трогает ввод игры (низкоуровневый хук мыши только в режиме наблюдателя) — ввод игры восстанавливается мгновенно после закрытия панели;
- **Отдельная консоль `dlssnr_console.exe`**: работает вне процесса игры, двусторонняя синхронизация в реальном времени через разделяемую память;
- **Компаньон-плагин ReShade** (`dlssnr-companion.addon64`): страница настроек в меню ReShade Home.

Любое изменение (включая горячую перезагрузку ini) мгновенно распространяется на все стороны.

### Графический менеджер `DLSS5NR-CostScaler-Manager.exe`

Полностью самописный интерфейс Material 3 Expressive на Win32 + GDI+ (нулевые зависимости времени выполнения), четыре страницы: **Быстрая установка** (рекурсивное сканирование библиотеки, установка / удаление / восстановление в один клик) · **Установленные** · **История** · **Отладка панели** (прямо пишет ini прокси, отложенная запись 500 мс).

### FPS Governor (0.7.0, синхронизация с апстримом)

Конечный автомат динамических ступеней разрешения: время кадра сглаживается EWMA (~30 кадров) и сравнивается с целевым FPS — ниже 95% цели в течение 1.0 с ступень вниз на 5%, выше 115% в течение 3.0 с ступень вверх на 5%, после каждого шага — пауза охлаждения (по умолчанию 2.0 с). Переключение ступеней использует многослотовый кеш конвейера для мгновенного перехода без ожидания; в **режиме Frame-Gen (FG)** цель оценивается по «частоте дисплея = базовая × множитель» для DLSS 3 / FSR 3 / Lossless Scaling 2x/3x/4x.

### Цепочка анти-мерцания при пропуске кадров (0.6.3 → 0.7.1 → 0.7.3, только в этой ветке)

При включённом чередовании кадров VRNR кадры с полным выводом и кадры пропуска чередуются на экране — чем ниже FPS и больше смещение за кадр, тем заметнее пульсация в чувствительной к глазу полосе частот. Здесь накоплены следующие исправления (главный переключатель `VrnrAntiFlicker`, включён по умолчанию):

- **Временной пандус (0.6.3, исправлен в 0.7.1)**: при 2+ последовательных пропусках сила остатка плавно снижается 100% → 90% → 72% → 55%; чередующийся паттерн (счётчик серии у каждого пропущенного кадра всегда равен 1) больше не получает ошибочную скидку — периодическая пульсация 10% устранена;
- **Пространственное сглаживание (0.6.3)**: вес затухания вычисляется по усреднённой разности яркости в окне 3×3 — собственный шум кадра больше не дёргает вес каждый кадр;
- **Симметричная защита светов (0.6.3)**: пропущенные кадры применяют ту же HDR-коррекцию ярких участков, обе ветки остаются одинаковыми в светах;
- **Нижний порог веса (0.7.1, эксперимент)**: вес edit пропущенных кадров не опускается ниже `VrnrWeightFloor` (по умолчанию 0.60) — движущиеся области больше не схлопываются в ноль и не «возвращаются рывком» на следующем кадре вывода;
- **Репроекция MV (0.7.1, эксперимент)**: пропущенные кадры выравнивают кеш нейронного входа 2-кадровой давности к текущему кадру по игровым векторам движения перед вычислением разности яркости — устраняет импульсное затухание всего экрана из-за «ложного обнаружения движения» на смещённом кадре; побеждает лучше выровненный образец, соглашение о знаке MV не важно;
- **Защита силуэтов (0.7.1, эксперимент)**: на разрывах глубины (контуры персонажей / объектов) вес edit пропущенных кадров ограничивается значением ≤0.10 — устаревший edit не создаёт «призраков» через силуэты;
- **Адаптация к FPS (0.7.3, эксперимент)**: при низком FPS сила edit **кадров вывода** плавно снижается (`VrnrAdapt`, включён по умолчанию), сокращая визуальный разрыв с пропусками с обеих сторон — чисто процессорная реализация, ноль новых GPU-ресурсов.

### Алгоритмический слой (синхронизирован с апстримом v1.0.5)

Аппаратное билинейное понижение разрешения (кеш тайлов LDS) → вывод NR в низком разрешении → **композитинг высокочастотного согласованного остатка** обратно на нативный кадр; **суперсэмплинг 25%–200%**, **анизотропное масштабирование** (эксперимент), **билатеральное сохранение силуэтов с учётом глубины**, HDR-ограничение яркости + резкость RCAS, динамическое отслеживание субпрямоугольников DRS, SDR / HDR10 PQ / scRGB / R11G11B10.

## Что это такое

Автономный прокси-DLL и набор инструментов для NVIDIA DLSS-NR (DirectX 12): нейросетевая модель выполняет вывод в пониженном разрешении, а шейдер «высокочастотного согласованного остатка» сохраняет нативные 1:1 геометрию, мелкие текстуры, текст и края — **стоимость DLSS-NR на GPU отвязывается от разрешения дисплея без потери чёткости**. Архитектура не зависит от хоста: подходит любой игре, движку или инжектору, вызывающему `nvngx_dlssnr.dll` через DirectX 12.

**Как это работает**: оригинальный DLL переименовывается в `nvngx_dlssnr_real.dll`; прокси перехватывает вызовы NGX — понижает разрешение нативного кадра (почти бесплатно), передаёт его DLSS-NR, затем композитит дельту нейросети обратно на нетронутый нативный кадр как согласованный остаток.

1. Положите менеджер вместе с прокси `nvngx_dlssnr.dll` и `nvngx_dlssnr.ini` в одну папку (распознаётся автоматически);

3. Запустите игру, нажмите `Ctrl+Alt+F11` для панели; или меняйте настройки на странице «Отладка панели» менеджера (в игре применится в течение секунды).

## Краткая справка по конфигурации (`nvngx_dlssnr.ini`)

Читается при запуске, затем горячая перезагрузка каждую секунду. Ниже краткая справка; **назначение и принцип каждого ключа — в следующем разделе «Подробный разбор конфигурации»**.

```ini
[DLSSNR_Proxy]
EnableProxy = 1              ; 1 = прокси активен; 0 = нативный проход
ResolutionScale = 0.75       ; масштаб разрешения вывода (0.25 ~ 2.00)
EnableAnamorphic = 0         ; анизотропное масштабирование (эксперимент)
ResolutionScaleX = 0.65      ; горизонтальный масштаб (0.25 ~ 2.00)
ResolutionScaleY = 0.85      ; вертикальный масштаб (0.25 ~ 2.00)
EnlargementMode = 1          ; 1 = согласованный остаток; 0 = билинейный
TransferStrength = 1.00      ; сила композитинга остатка (0 ~ 2)
ColorStrength = 1.00         ; сила цвета (0 ~ 1)
Sharpness = 0.20             ; резкость RCAS (0 ~ 1)
EnableDepthAwareResolve = 1  ; сохранение силуэтов с учётом глубины
EnableAlternatingFrames = 0  ; чередование кадров VRNR (эксперимент, по умолчанию выкл.)
VrnrAntiFlicker = 1          ; главный выключатель анти-мерцания (по умолчанию вкл.)
VrnrWeightFloor = 0.60       ; нижний порог веса edit (эксперимент, 0 ~ 1)
VrnrReproject = 1            ; репроекция векторов движения (эксперимент)
VrnrAdapt = 1                ; адаптация к FPS (эксперимент, 0.7.3)
VrnrAdaptAmount = 0.60       ; максимальная доля затемнения (0 ~ 1)
VrnrAdaptFpsHi = 45          ; затемнение начинается ниже этого FPS
VrnrAdaptFpsLo = 25          ; полное затемнение на этом FPS и ниже
EnableHotkeys = 1            ; главный выключатель горячих клавиш в игре
EnableUi = 1                 ; главный выключатель внутриигровой панели
UiLanguage = 0               ; язык панели: 0 中 / 1 EN / 2 RU / 3 한
PanelX/Y/W/H = ...           ; положение / размер окна панели (сохраняется автоматически)

[DLSSNR_Settings]
UseCustomSettings = 0        ; 0 = передавать параметры NR вызывающей стороны; 1 = переопределить
Style = 0                    ; 0 = баланс / 1 = резкость / 2 = кино
Intensity = 1.00             ; сила реконструкции (0 ~ 2)
LocalStructureStrength = 1.00  ; сохранение локальной структуры (0 ~ 2)
LocalToneStrength = 1.00       ; локальный тон (0 ~ 2)
SkinStructureStrength = -1.00  ; структура кожи (-1 = авто, 0 ~ 2)
UseAutoMask = 0              ; автомаскирование быстрого движения / мелких элементов

[Hotkeys]
RequireCtrlAlt = 1           ; требуют ли горячие клавиши префикса Ctrl+Alt
KeyToggleProxy = 32          ; переключить прокси (код VK, 32 = Space)
KeyToggleMode = 35           ; переключить режим (35 = End)
KeyScaleUp = 33              ; увеличить масштаб (33 = PageUp)
KeyScaleDown = 34            ; уменьшить масштаб (34 = PageDown)
KeyToggleUI = 122            ; вызвать панель (122 = F11)

[Governor]
EnableGovernor = 0           ; динамический Governor разрешения (по умолчанию выкл.)
TargetFps = 60.0             ; целевой бюджет FPS (30 ~ 240)
MinScale = 0.50              ; минимальная ступень масштаба
MaxScale = 1.00              ; максимальная ступень масштаба
HysteresisSec = 2.0          ; пауза охлаждения между шагами (сек)
EnableFgMode = 0             ; режим цели Frame-Gen
FgMultiplier = 2.0           ; множитель FG (2/3/4)
```

## Подробный разбор конфигурации: назначение и принцип каждого переключателя

### Прокси и масштабирование (`[DLSSNR_Proxy]`)

| Ключ | Назначение | Принцип |
| --- | --- | --- |
| `EnableProxy` | Главный выключатель прокси. 0 = все вызовы NGX проходят без изменений, поведение в точности как у оригинального DLL | Горячие клавиши / панель переключают на ходу; переключение меняет только решение о масштабировании на пути перехвата — D3D-ресурсы не пересоздаются |
| `ResolutionScale` | Разрешение нейровывода. 0.75 ≈ 40% экономии (рекомендуемая золотая середина); 0.50 = пропорция DLSS Performance; 2.00 = суперсэмплинг 200% (DLDSR / фото) | Стоимость вывода пропорциональна числу пикселей. Масштабируется только **внутренний буфер, подаваемый модели**; итог всегда композитится обратно на полноформатный нативный кадр, поэтому понижение ≠ потеря детализации |
| `EnableAnamorphic` + `ResolutionScaleX/Y` | (Эксперимент) независимые горизонтальные / вертикальные масштабы вместо единого | В широкоэкранных сценах вертикальная детализация важнее; комбинация 0.65×0.85 экономит ещё ~45% нагрузки с ровным темпом кадров. Каждая ось понижается и повышается независимо |
| `EnlargementMode` | 1 = согласованный остаток (рекомендуется); 0 = билинейный вывод + RCAS | Согласованный остаток: нативные 1:1 пиксели — якорь, назад добавляется только **дельта (edit)** нейровывода — геометрия, текст и UI свободны от потерь по построению. Билинейный: вывод масштабируется напрямую, резкость спасает RCAS — потерь больше |
| `TransferStrength` | Сила композитинга остатка (0 ~ 2). 1.0 = передать дельту как есть; 0 = чистый нативный кадр | Остаток = вывод нейросети − пониженный вход. Масштабирование множителя масштабирует дельту: ниже — «нативнее», выше (>1) — выразительнее изменения света |
| `ColorStrength` | Сила цвета (0 ~ 1). 0 = сохранение исходного оттенка, масштабируется только яркость | Дельта раскладывается на яркостную и цветовую составляющие: 1.0 сохраняет полный нейроцвет (отражённый свет / цвета материалов), 0 оставляет только яркостную дельту, масштабируемую по вектору цветности нативного пикселя, устраняя тонирование / выцветание (апстрим 15f09dd) |
| `Sharpness` | Контрастно-адаптивная резкость RCAS (0 ~ 1) | FidelityFX RCAS: вес резкости адаптируется к диапазону яркости окрестности (слабее на плоских участках, сильнее на краях) без выбросов. Автоотключается при многопроходной записи в один буфер, предотвращая экспоненциальные звонкие края |
| `EnableDepthAwareResolve` | Билатеральное сохранение силуэтов по глубине | Берёт 4 соседей нативного буфера глубины, обнаруживает разрывы (контуры геометрии); на силуэтах вес низкочастотной нейродельты снижается (до 0.25), чтобы низкоконтрастный свет не «перетекал» через передний край |

### Цепочка VRNR чередования кадров (эксперимент)

| Ключ | Назначение | Принцип |
| --- | --- | --- |
| `EnableAlternatingFrames` | Вывод DLSS-NR выполняется каждый 2-й кадр; промежуточные кадры переиспользуют предыдущий нейро-edit, поднимая средний FPS | Кадры вывода идут полной цепочкой; пропущенные запускают только композитинг — **кешированный устаревший edit** с весом по разности яркости. Чем сильнее рассогласование с текущим кадром, тем ниже вес (картинка возвращается к нативным пикселям). Цена: пилообразный темп кадров и пульсация яркости → см. три строки ниже |
| `VrnrAntiFlicker` | Главный выключатель анти-мерцания (0.6.3 тройное исправление + улучшения 0.7.1/0.7.3) | См. раздел «Цепочка анти-мерцания» выше. Выкл. = поведение в точности 0.6.2 |
| `VrnrWeightFloor` | (Эксперимент) нижний порог веса edit пропущенных кадров (по умолчанию 0.60, 0 = выкл.) | Сильное движение → большая разность яркости → вес → 0 → следующий кадр вывода внезапно восстанавливает полную силу: скачок «схлопывание ↔ восстановление». С порогом движущиеся области сохраняют минимум 60% остатка, восстановления больше не скачут. Выше — стабильнее, ниже — меньше «призраков» |
| `VrnrReproject` | (Эксперимент) репроекция векторов движения (по умолчанию вкл.) | При панорамировании нейровход 2-кадровой давности смещён относительно текущего кадра, и разность яркости ошибочно распознаётся как «движение» — экран целиком затухает. Здесь устаревший вход сначала **выравнивается** по игровому MVec к текущему кадру, затем считается разность; при неверном выравнивании разность естественно больше — побеждает лучший образец, знак MV не важен. При недоступности MVec — автоматический откат |
| `VrnrAdapt` | (Эксперимент, 0.7.3) главный выключатель адаптации к FPS | При низком FPS смещение за кадр больше, веса пропусков падают сильнее, и разрыв с полносильными кадрами вывода даёт пульсацию в чувствительной полосе 15–22 Гц. Переключатель **приглушает кадры вывода** при низком FPS, сокращая разрыв с обеих сторон. Чисто процессорная реализация: EWMA-сглаженный FPS даёт коэффициент 0–1, передаваемый одним шейдерным константом — ноль новых GPU-ресурсов |
| `VrnrAdaptAmount` | Максимальная доля приглушения (0 ~ 1, по умолчанию 0.60). 1.00 = при очень низком FPS нейро-edit кадра вывода полностью подавляется | Балансирует с затуханием кадров пропуска: пропуски приглушает цепочка весов, кадры вывода — этот коэффициент; чем меньше разрыв, тем меньше пульсация |
| `VrnrAdaptFpsHi` / `VrnrAdaptFpsLo` | Окно smoothstep-приглушения (по умолчанию 45 / 25) | При EWMA FPS ≥ Hi изменений нет; Hi→Lo — плавный переход (smoothstep убирает «ступенчатость»); ≤ Lo — полное приглушение `VrnrAdaptAmount` |

### FPS Governor (`[Governor]`)

| Ключ | Назначение | Принцип |
| --- | --- | --- |
| `EnableGovernor` | Динамические ступени разрешения: автоматически меняет `ResolutionScale`, удерживая целевой FPS | Время кадра проходит фильтр выбросов (>80 мс экраны загрузки / ≤0.5 мс отбрасываются), затем EWMA ~30 кадров; эффективный FPS < 95% цели в течение 1.0 с — ступень вниз 5%, > 115% в течение 3.0 с — вверх 5%, после каждого шага пауза охлаждения против колебаний |
| `TargetFps` | Целевой бюджет FPS (30 ~ 240) | Governor меняет ступени только между `MinScale` и `MaxScale`; за границами останавливается |
| `MinScale` / `MaxScale` | Границы ступеней масштаба (0.25 ~ 2.00) | Шаг ступеней — 5%; переключение использует многослотовый кеш конвейера для мгновенной замены 0 мс (промежуточные буферы разных масштабов постоянно резидентны) |
| `HysteresisSec` | Пауза охлаждения между шагами (0.5 ~ 10.0 с, по умолчанию 2.0) | Предотвращает «дыхание» разрешения от частых переключений возле порога |
| `EnableFgMode` | Режим цели Frame-Gen | С генерацией кадров «частота дисплея = базовая × множитель». Включённый режим оценивает `TargetFps` по **частоте дисплея**, исключая ошибочное понижение при FG |
| `FgMultiplier` | Множитель FG (2.0 / 3.0 / 4.0) | Соответствует DLSS 3 / FSR 3 / Lossless Scaling 2x/3x/4x; эффективный FPS = измеренный × множитель |

## Системные требования

- Windows 10 / 11 (64 бита)
- Видеокарта NVIDIA RTX (серии RTX 20 / 30 / 40 / 50)
- Игра или плагин, использующие NVIDIA DLSS-NR (`nvngx_dlssnr.dll`) через DirectX 12

## Сборка (x64, MSVC)

```text
build.bat
```

Выполняет весь конвейер: компиляция HLSL-шейдеров (fxc) → ресурс версии → прокси-DLL → консоль → менеджер. Результаты — в `build\<версия>\`, промежуточные файлы — в `build\obj\`; версия поддерживается в `build.bat` (`VERSION`) и `app_version.rc`. Компаньон-плагин собирается отдельно: `companion\build_companion.bat`.

## Частые вопросы

- **Папка игры в Program Files?** Запустите менеджер от администратора или установите вручную.
- **Панель не получает мышь?** Панель использует низкоуровневый хук мыши в режиме наблюдателя и не конкурирует с игрой за ввод; если античит блокирует — сообщите.
- **Стоит ли включать чередование кадров VRNR?** Да — с цепочкой анти-мерцания по умолчанию (`VrnrAntiFlicker` / `VrnrWeightFloor` / `VrnrReproject` / `VrnrAdapt` все включены). Если при низком FPS остаётся лёгкая пульсация — поднимите `VrnrAdaptAmount` до 0.8–1.0; если картинка кажется блёклой — снизьте.
- **В журнале сбоев `DXGI_ERROR_DEVICE_REMOVED`?** Это сброс драйвера GPU (TDR), к панели отношения не имеет (панель не трогает D3D-устройство игры); проверьте разгон / версии драйверов.
